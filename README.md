# Первое создание фототура Airbnb

Хозяин объявления запускает создание фототура из уже загруженных фотографий. Система распределяет снимки по типам помещений, даёт хозяину поправить результат и показывает сохранённые группы. Загрузка снимков, повторная сортировка, показ гостю и бронирование за рамками схем. Контур обучения показан от сбора ручных правок до публикации следующей версии модели.

## Что решает модель

Классификатор получает пиксели каждого снимка и возвращает тип помещения и оценку уверенности. Сервис фототуров получает предсказания вместе с версией модели и собирает группировку. Хозяин получает предложенную раскладку и может изменить её. Автоматическая сортировка сокращает ручную работу при создании тура и помогает гостям ориентироваться в объявлении.

## Допущения

- Сервис объявлений возвращает идентификаторы фото и ссылки с ограниченным доступом. ML-сервис читает снимки, декодирует их, приводит к нужному размеру и нормализует пиксели. Одна версия классификатора обслуживает весь запрос. Группы соответствуют типам помещений, поэтому снимки двух разных спален могут попасть в одну группу.
- Сервис фототуров использует предсказание для фото, если оценка **не ниже 0,80**. При меньшей оценке, отсутствии класса или ответа для отдельного снимка он предлагает группу «Дополнительные фото». При недоступности модели, тайм-ауте или ошибке всего запроса туда попадут все снимки. Порог 0,80 — выбранная стартовая граница, которую нужно проверить на размеченной выборке. Хозяин может назначить комнату вручную или оставить снимок в дополнительных.
- Хозяин сохраняет просмотренный черновик. Если он явно перенёс или назначил снимок в комнату, после сохранения система записывает выбранный тип по идентификатору фото вместе с исходным предсказанием, если оно было. Молчаливое принятие предложения и перенос в «Дополнительные фото» меток класса не дают.
- Задача обучения периодически использует разрешённые для этого снимки и ручные метки. Они отражают правки хозяев, поэтому точность по ним описывает только эту выборку. Перед сменой версии модель проверяется на независимо размеченных фото из объявлений, которые не использовались для обучения. Задача публикует прошедшую проверку версию в реестре и указывает её для следующего инференса.

## Как соотносятся BPMN и C4

| Действие на BPMN | Контейнер C4 |
| --- | --- |
| Запросить создание, проверить раскладку, назначить комнаты и увидеть итог | Веб-редактор фототура |
| Получить ссылки на фото, распределить снимки и показать черновик | Сервис фототуров |
| Вызвать ML-сервис классификации фото с тайм-аутом | Сервис фототуров делает запрос, ML-сервис классификации возвращает типы, оценки и версию |
| Сохранить группы и записать ручные метки для оценки и обучения | Сервис фототуров передаёт группы в Сервис объявлений, а метки — в Хранилище разметки |

Обратную связь из Хранилища разметки читает Задача обучения. Следующая версия модели публикуется в Реестре моделей.

## Источники

- Создание тура из редактора объявления, автоматическая сортировка и ручные правки описаны в [справке Airbnb о фототурах](https://www.airbnb.com/help/article/477).
- Группа «Дополнительные фото» для нераспознанных снимков описана в [руководстве Airbnb по обновлению объявления](https://www.airbnb.com/resources/hosting-homes/a/refresh-your-listing-661).
- Обозначения и уровни сверены с [примерами BPMN от Camunda](https://camunda.com/bpmn/examples/) и [описанием C4](https://c4model.com/).

На схемах я реконструировал границы и состав сервисов, технологии, формат запроса и ответа модели, порог, обработку сбоев и способ превращать ручные правки в данные для обучения.
